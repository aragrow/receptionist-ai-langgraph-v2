Example Usage (Preview)
python# In a subclass (e.g., ReceptionistL1):
class ReceptionistL1(BaseAgent):
    def __init__(self):
        super().__init__(
            agent_name="receptionist_l1",
            agent_tier="L1",
            temperature=0.2,  # Lower temperature for L1 (more deterministic)
            max_tokens=300    # L1 needs fewer tokens
        )
    
    async def process(self, state: WorkflowState) -> L1Output:
        # Build prompt
        prompt = self.build_prompt(state)
        
        # Call LLM
        llm_response = await self.call_llm(prompt, system_instruction=self.system_prompt)
        
        # Parse JSON
        output = self.parse_llm_json(llm_response, L1Output)
        
        # Calculate confidence if not provided
        if not output.confidence:
            output.confidence = self.calculate_confidence(llm_response, output.dict())
        
        return output
    
    def build_prompt(self, state: WorkflowState) -> str:
        return f"Classify this user input: {state.speech_text}"

What We Built:
src/agents/l3_base_agent.py - Base class for all domain specialist agents
🎯 L3 Agent Responsibilities:

Validate Prerequisites - Ensure all required information is present
Execute Actions - Perform domain-specific operations (bookings, tickets, payments, etc.)
Generate Confirmations - Create user-facing messages using LLM
Provide Next Steps - Guide user on what happens next
Handle Errors - Graceful failure with recovery options


🔧 Key Features:
Action Execution Framework:

Abstract execute_action() method for domain logic
Abstract validate_prerequisites() for pre-flight checks
Abstract get_supported_actions() for capability registration
Intent-to-action mapping

Confirmation Generation:

Uses LLM (Gemini Pro) to generate natural confirmations
Context-aware messages (includes customer name, booking details, etc.)
Fallback templates if LLM fails
2-3 sentence conversational tone

Next Steps Logic:

Action-specific guidance
Up to 3 next steps per action
Recovery steps for failures
Sets clear expectations

Validation Helpers:

_check_required_slots() - Verify all slots filled
_validate_entity_format() - Format validation (phone, email, date)
Returns clear error messages

Error Handling:

Prerequisite failures (missing information)
Action execution failures (system errors)
LLM failures (fallback confirmations)
Escalation triggers


🏗️ Architecture:
L3BaseAgent (abstract)
│
├── get_supported_actions()      [abstract - list capabilities]
├── execute_action()              [abstract - do the work]
├── validate_prerequisites()      [abstract - check requirements]
│
├── process()                     [implemented - main flow]
├── _determine_action()           [implemented - intent→action]
├── _generate_confirmation()      [implemented - LLM messaging]
├── _determine_next_steps()       [implemented - guidance]
└── _update_state_with_l3_output()[implemented - state management]

🎯 Processing Flow:
1. L3 receives state from L2 with:
   - Refined intent
   - Extracted entities
   - Filled slots

2. Determine action from intent
   → "book_home_cleaning" maps to "create_booking"

3. Validate prerequisites
   → Check all required slots present
   → Validate entity formats
   → Return error if invalid

4. Execute action
   → Run domain-specific logic
   → Create DB records
   → Send emails/notifications
   → Return result data

5. Generate confirmation
   → Use LLM with action results
   → Create natural language message
   → Include key details

6. Determine next steps
   → Action-specific guidance
   → Set expectations
   → Provide options

7. Update state
   → Store results
   → Mark as processed
   → Add to routing history

8. Return updated state

🛡️ Error Handling:
Scenario 1: Missing Prerequisites
python# Missing required slot "address"
→ validate_prerequisites() returns (False, "Missing required information: address")
→ Create error L3Output
→ Message: "I need some additional information... Missing required information: address"
→ Does NOT execute action
→ May trigger clarification or escalation
Scenario 2: Action Execution Failure
python# Database error during booking creation
→ execute_action() returns {"success": False, "error_message": "Database timeout"}
→ L3Output with ActionStatus.FAILED
→ Message: "I apologize, but I was unable to complete your request: Database timeout"
→ Next steps: ["Please try again or contact support for assistance"]
Scenario 3: LLM Confirmation Failure
python# LLM API error
→ _generate_confirmation_message() catches exception
→ Falls back to template: "Your request has been processed successfully..."
→ Action still succeeded, just using fallback message
